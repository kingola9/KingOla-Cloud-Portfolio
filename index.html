What I Do

What I Do — In Simple Terms

Think of me as the person you can call when technology isn't working the way it should.

I help troubleshoot technology problems, support computers and systems, work with cloud infrastructure, and investigate practical solutions when something goes wrong.

When a Computer or System Isn't Working

"A computer is not working properly, a system is slow, or something that previously worked suddenly stops working."

What I do: Investigate the problem, identify the likely cause, troubleshoot it, and work toward a practical solution.

When Technology Cannot Connect

"An employee cannot connect properly to a network or access a service they need for work."

What I do: Investigate the connectivity or configuration issue and work through the problem systematically.

When a Business Uses Cloud Services

"A business may rely on cloud-based servers, storage, applications, and other services instead of keeping everything on physical computers."

What I do: Work with Microsoft Azure resources and support cloud infrastructure through configuration, organization, troubleshooting, and documentation.

When something stops working, instead of simply saying "it's not working," I approach the problem systematically:

Identify what is happening and clarify the issue.

02

Investigate

Gather information, examine configurations, logs, settings, and system behavior.

03

Narrow the problem down to the most likely cause.

04

Resolve

Apply a practical solution and test the result.

05

Document

Document the solution and lessons learned for future troubleshooting.

Project 1

Azure Virtual Machine Deployment & Troubleshooting

Deployed and troubleshot an Ubuntu 22.04 LTS virtual machine in Microsoft Azure using Azure Portal, Azure CLI, SSH, VM configuration, and managed disks.

Microsoft AzureVirtual MachinesUbuntu LinuxAzure CLISSH
View Documentation
Objective

Stand up a working Linux VM in Azure and gain hands-on familiarity with the deployment workflow end to end.

Problem / Scenario

Getting a reliable, remotely accessible Ubuntu server running in the cloud, with secure authentication and correct disk configuration.

Architecture / Workflow

Resource group → virtual network → Ubuntu 22.04 LTS VM → managed OS disk → public IP with SSH access.

Implementation

Provisioned the VM through the Azure Portal and Azure CLI, configured the OSProfile for authentication, and validated connectivity over SSH.

Troubleshooting & Challenge

Resolved SSH access issues, adjusted password authentication settings, and corrected managed disk and OSProfile configuration problems.

Solution & Result

A functioning, remotely accessible VM with correctly configured authentication, disk, and power state (including proper deallocation to control cost).

Lessons Learned

Deepened understanding of Azure VM authentication models, managed disks, and the practical impact of deallocation on billing and state.

Project 2

Standardizing VM Deployments Using Azure Custom Images & ARM Templates

Created a reusable VM deployment workflow by generalizing a virtual machine, creating a custom image, and working with ARM templates.

Azure Virtual MachinesCustom ImagesARM TemplatesAzure Portal
View Documentation
Objective

Build a repeatable deployment pattern so new VMs don't need to be configured manually from scratch each time.

Problem / Scenario

Manual, inconsistent VM setup wastes time and introduces configuration drift across deployments.

Architecture / Workflow

Generalized source VM → captured custom image → ARM template referencing the image for repeatable provisioning.

Implementation

Generalized a configured VM, captured it as a custom image, then wrote and deployed an ARM template that provisions new VMs from that image.

Troubleshooting & Challenge

Worked through generalization prerequisites and template parameter/resource dependency ordering.

Solution & Result

A reusable image and template pair that can reliably produce a pre-configured VM on demand.

Lessons Learned

Hands-on grasp of infrastructure-as-code fundamentals and why standardization matters at scale.

Project 4

Azure Resource Organization & Protection with Tags and Locks

Organized Azure resources using tags and implemented resource locks to improve resource management and help prevent accidental changes or deletion.

Azure Resource GroupsTagsResource LocksAzure Portal
View Documentation
Objective

Keep cloud resources organized and protect critical ones from accidental changes or deletion.

Problem / Scenario

Untagged, unprotected resources are hard to track and easy to accidentally delete or modify.

Architecture / Workflow

Resource groups → tagging strategy applied across resources → CanNotDelete / ReadOnly locks on critical resources.

Implementation

Applied a consistent tagging scheme and configured resource locks on key resources to prevent unintended changes.

Troubleshooting & Challenge

Worked through lock inheritance behavior and how locks interact with management operations.

Solution & Result

A clearly organized resource group with governance controls protecting critical infrastructure.

Lessons Learned

Practical grounding in cloud governance — a core part of responsible resource management.

Why This Matters

Why IT Support Matters

Technology is supposed to help people work efficiently. When computers, applications, networks, or cloud services stop working, valuable time can be lost.

  • An employee cannot access an important system → work can be delayed.
  • A cloud resource stops working → a service or application may become unavailable.
  • A recurring technical problem is not properly investigated → the same issue may continue to return.
  • Employees spend too much time trying to solve technical problems themselves → less time is available for their actual responsibilities.

Good technical support helps investigate these problems, resolve issues, and keep technology working as intended.
